## 0. エグゼクティブサマリー

現行ツールは「ジェネレーター」と名乗っているが、実態は **約51個の固定HTMLスニペットを連結するセクションカタログ** である。全てのLPが同じ汎用コピー(「ビジネスの成長を加速させる」等)で始まり、ユーザーが手作業で書き換える前提になっている。これが「精度が非常に悪い」と感じられる根本原因であり、ランダム性の問題ではない(出力は完全に決定的)。

さらに調査により、以下の **構造的な欠陥** が判明した:

1. **編集ラウンドトリップの破綻**: インライン編集した本文はテーマ変更・並び替え・undo等の再レンダーで消失し、**エクスポートHTMLにも一切反映されない**(画像差し替えのみ生存)
2. **プレビューのスタイル非隔離**: プレビューがiframeではなく同一ドキュメントへの`innerHTML`注入のため、ツールUIと生成LPのCSSが衝突(過去の「デザイン破綻」修正コミットの原因)
3. **AI統合はあるが安全でない**: APIキーがlocalStorageに平文保存、ブラウザから直接プロバイダを呼ぶ構成

本計画は、**「セクションカタログ」から「目的駆動(intent-driven)のデザイン生成システム」への転換** を柱に、(a) JSONデータモデルを唯一の真実とする編集/更新スキーム、(b) 各プロバイダの最安+2番目に安いモデルによる2ティアAIルーティング、(c) 3ペイン+ウィザードのUX刷新、を5フェーズで実施する。

## 3. コア設計方針

### 3.1 データモデル中心設計 — JSONを唯一の真実に

現状の「HTML文字列が状態」をやめ、**LPプロジェクトJSON(スキーマバージョン付き)を唯一の真実(Single Source of Truth)** とする。編集・AI・保存・エクスポートすべてがこのJSONを介する。

```jsonc
{
  "schemaVersion": 3,
  "meta": { "title": "...", "description": "...", "ogImage": null },
  "brief": {                       // ← 定性的な目的情報を一級市民として保持
    "industry": "SaaS",
    "purpose": "無料トライアル獲得",
    "audience": "中小企業の経営者",
    "tone": "信頼感・プロフェッショナル",
    "differentiators": ["導入5分", "国内サポート"],
    "cta": { "primary": "無料で試す", "secondary": "資料請求" }
  },
  "theme": {
    "presetId": "trust-blue",
    "tokens": { "--color-primary-500": "#2563eb", "...": "..." },
    "fontPairing": { "heading": "Noto Sans JP", "body": "Noto Sans JP" },
    "darkMode": false
  },
  "sections": [
    {
      "id": "sec_a1b2",
      "type": "hero-split",        // レイアウトバリアント
      "content": {                 // ← コンテンツとマークアップを分離
        "headline": "…",
        "subheadline": "…",
        "stats": [{ "value": "50K+", "label": "利用社数" }],
        "image": { "src": "...", "alt": "..." }
      },
      "options": { "align": "left", "background": "gradient" }
    }
  ],
  "history": { "savedAt": "...", "revision": 12 }
}
```

**効果**:
- **ラウンドトリップ問題(課題#2)の構造的解消**: レンダラは常に `JSON → HTML` の純関数。編集=JSON更新→再レンダー。エクスポートも同じレンダラを使うため、編集が消える経路が存在しなくなる
- **AI連携の精度向上**: AIにHTMLを書かせるのではなく**JSONコンテンツを書かせる**(§4.2)。マークアップ品質はテンプレート側で保証されるため、「AIがCSSクラスを間違える/構造を壊す」問題が原理的に消える
- undo/redoはJSONスナップショット(またはJSON Patch)で堅牢化。既存の`history[]`方式を移植可能

既存テンプレート(`templates.js`)は資産として、`{型: (content) => html}` のレンダラ関数群に変換して再利用する。全51種を一括変換するのではなく、利用頻度の高い型から段階的に移行する(§8 Phase 1)。

### 3.2 ブリーフファーストUX — 「選ばせる」から「聞き出す」へ

現状は最初に60個のセクションボタンを提示するが、再設計では **目的の定性情報(ブリーフ)を先に聞く**:

```
Step 1: ブリーフ入力       業種 / 目的(CV定義) / ターゲット / トーン / 強み / CTA文言
        (フォーム+自由記述。AIが自由記述から構造化してフォームに反映)
Step 2: AI提案            構成案(セクション列)+コピー+配色+フォントを2〜3案提示
        (プレビュー付きで比較選択。気に入らなければ再生成/手動構成にフォールバック)
Step 3: エディタで調整      3ペインUI(§5)で編集。AIアシストは常駐
Step 4: エクスポート/公開   HTML(自己完結)/React/Vue/JSON
```

ブリーフはプロジェクトJSONに保持され続けるため、**後からのAIリライト・レビュー・追加セクション生成が常に文脈を持つ**(現状のAI機能は毎回業種を聞き直している)。

### 3.3 デザイン品質エンジン

生成物の品質を「AI任せ」にせず、決定的なルールで底上げする:

- **トークン一元化**: デザイントークンを `css/tokens.css` の1ファイル(`:root`は1箇所)に統合。テーマ=トークンセットのオーバーライドのみ、と定義
- **キュレーション済みプリセット**: テーマは「色相を変えただけの9種」ではなく、**配色+フォントペアリング+角丸/影/間隔の性格をセットにしたスタイルプリセット**(例: Trust Blue/コーポレート、Warm Minimal/サービス業、Bold Vibrant/スタートアップ、Elegant Serif/高級・美容 など8〜12種)として再設計。業種→推奨プリセットのマッピングをAI構成提案に組み込む
- **WCAG自動検証**: テーマ適用時・AIパレット生成時にコントラスト比(本文4.5:1、大見出し3:1)をクライアントサイドで計算し、不合格の組合せは自動補正 or 警告
- **アイコン刷新**: テンプレート内の絵文字アイコンをSVGアイコンセット(Lucide等、ローカル同梱)に置換
- **ダークモード一元化**: `data-theme`属性方式に統一し、`body.dark-mode`系を廃止

### 3.4 プレビューの隔離 — iframe化

プレビューを `<iframe srcdoc>` に変更し、生成LPのCSS/フォントをiframe内だけで読み込む。ツールUIと生成物のカスケードを完全分離(課題#3の解消)。デバイスプレビューもiframe幅切替で実装が単純化する。インライン編集はiframe内documentへのイベント委譲で継続可能。

## 4. AI統合設計

### 4.1 モデル戦略 — 各社「最安+2番目に安い」の2ティア構成

要件どおり、OpenAIとGeminiそれぞれの**最安モデル(Draftティア)**と**2番目に安いモデル(Qualityティア)**の計4モデルをサポートする。2026年7月時点の調査結果:

| プロバイダ | ティア | モデルID | 価格(入力/出力, per 1M tokens) | 割当タスク |
|-----------|--------|---------|-------------------------------|-----------|
| OpenAI | Draft(最安) | `gpt-5.4-nano` | $0.20 / $1.25 | セクション別コピー生成、リライト、alt/SEOメタ |
| OpenAI | Quality(2番目) | `gpt-5.4-mini` | $0.75 / $4.50 | 構成プラン、パレット生成、デザインレビュー |
| Gemini | Draft(最安) | `gemini-2.5-flash-lite` | $0.10 / $0.40 | 同上(Draft) |
| Gemini | Quality(2番目) | `gemini-3.1-flash-lite` | $0.25 / $1.50 | 同上(Quality) |

> **注意**: モデルラインナップと価格は改定が頻繁(旧`gpt-4o-mini`系は既に公式価格表から消えている)。実装時に公式価格ページ(OpenAI: developers.openai.com/api/docs/pricing、Google: ai.google.dev/gemini-api/docs/pricing)で再確認し、`AIService.PROVIDERS` の定義は**設定ファイル化して差し替え可能**にする。「最安/2番目」が入れ替わった場合もコード変更なしで追従できるようにする。

**タスク→ティアのルーティング表**(`AIService`に`tier`概念を追加):

| タスク | ティア | 理由 |
|--------|--------|------|
| ブリーフ構造化(自由記述→JSON) | Draft | 単純変換 |
| 構成プラン(セクション列+方針) | **Quality** | LP全体の品質を左右する最重要判断 |
| セクション別コンテンツ生成 | Draft | プラン+スキーマ制約下の穴埋めで十分。件数が多くコスト支配的 |
| カラーパレット/フォント提案 | **Quality** | 少量トークンなのでコスト影響小、品質影響大 |
| デザインレビュー(スコア+改善提案) | **Quality** | 分析タスク |
| 部分リライト・トーン変換・翻訳 | Draft | 高頻度・低単価にすべき操作 |
| SEOメタ・alt生成 | Draft | 単純生成 |

失敗時フォールバック: Draftの出力がスキーマ検証に2回失敗したら同一タスクをQualityに昇格して再試行。

### 4.2 精度改善の本丸 — 「HTML生成」から「構造化コンテンツ生成」へ

現状AIは「CSSクラス許可リスト付きでHTMLを書け」というプロンプトで、モデルがクラスを誤用・構造破壊するリスクを常に抱える。再設計では:

1. **AIはJSONだけを返す**: 各セクション型に対応するJSONスキーマ(§3.1の`content`)を提示し、**Structured Output / JSONモード**で生成させる(OpenAI・GeminiともOpenAI互換エンドポイントで`response_format`/`response_schema`をサポート)
2. **レンダリングはテンプレートが担当**: マークアップ・クラス・アクセシビリティ属性はレンダラ関数が保証
3. **検証パイプライン**: JSONスキーマ検証(AJV等) → 文字数制約(見出し上限等) → NGワード → 失敗時リトライ/ティア昇格

これにより「AI精度が悪い」問題は「コピーの質」の問題に縮退し、安価なモデルでも安定した出力が得られる。既存の`AIStreamHandler`のHTML抽出・regexサニタイズは、この方式ではフリーフォームチャット経路のみに限定利用(将来的にDOMPurify導入)。

### 4.3 AIサポート機能一覧(優先度付き)

| 優先 | 機能 | 説明 |
|------|------|------|
| P0 | ブリーフ→構成+コピー一括生成 | §3.2のコアフロー。プラン(Quality)→各セクション並列生成(Draft) |
| P0 | セクション単位の再生成/リライト | 「もっと簡潔に」「トーンをカジュアルに」等のワンクリック指示+自由入力 |
| P0 | パレット/フォント提案 | ブリーフ+ベースカラーからトークンセット生成、WCAG検証つき |
| P1 | デザインレビュー | 構成/ビジュアル/CV導線/A11y/モバイルの5軸スコア+改善提案(既存`buildDesignReviewPrompt`を発展)。改善提案は「ワンクリック適用」可能なJSON Patch形式で返させる |
| P1 | A/B代替案生成 | 見出し・CTAの複数案を並列生成して選択UI |
| P2 | SEOメタ/OGP/alt一括生成 | 既存SEOパネルと統合 |
| P2 | 画像プロンプト提案 | 画像生成は当面スコープ外とし、プレースホルダー+altと「外部生成用プロンプト」提示に留める |

**UX原則**: すべてのAI操作は (a) 実行前に推定コスト表示、(b) ストリーミング表示(既存実装を活用)、(c) 適用前プレビュー+ワンクリックで元に戻せる(JSONスナップショット)、(d) 適用は必ずundo履歴に積む。

### 4.4 コスト試算(フル生成1回・7セクション想定)

概算トークン: プラン(入1.5k/出0.8k)+セクション7本(入計7k/出計3.5k)+パレット(入0.7k/出0.5k)+レビュー(入4k/出1.5k)

| 構成 | 概算コスト/回 |
|------|--------------|
| Gemini構成(flash-lite + 3.1-flash-lite) | 約$0.008(約1.2円) |
| OpenAI構成(5.4-nano + 5.4-mini) | 約$0.023(約3.5円) |

→ 目標の$0.03/回以内に収まる。リライト等の日常操作は1回$0.001未満。

### 4.5 セキュリティ改善

- **デフォルトをsessionStorageに変更**(現状はlocalStorageがデフォルト、`ai-service.js:63`)。localStorage永続化は「リスクを理解した」明示オプトインに
- キー表示は常にマスク、設定UIへのキー再エコー(`ai-ui-controller.js:366`)を廃止
- 将来オプション: サーバーレスプロキシ(Cloudflare Workers等)経由モードを追加し、キーをブラウザに置かない構成を可能に(OpenAIブラウザ直コールのCORS不安定も同時に解消)。個人利用はBYOK直コール、商品化時はプロキシ、の二段構え
- AI出力のサニタイズはDOMPurify(許可タグ/属性リスト方式)へ移行し、`<form>`/`<input>`を誤って除去しない

## 5. UI/UX再設計

### 5.1 画面構成 — 3ペイン+ステップナビ

```
┌────────────────────────────────────────────────────────────┐
│ ヘッダー: プロジェクト名 | 保存状態 | undo/redo | デバイス切替 | エクスポート │
├──────────┬──────────────────────────────┬──────────────────┤
│ 左: 構成  │ 中央: プレビュー(iframe)       │ 右: インスペクタ    │
│ ・セクション│  ・デバイス幅切替/ズーム        │ ・選択中セクションの │
│   ツリー   │  ・セクション選択ハイライト      │   編集フォーム      │
│  (D&D並替) │  ・インライン編集              │ ・テーマ/トークン    │
│ ・追加ボタン│                              │ ・AIアシスト        │
│ ・AIチャット│                              │  (タブ切替)        │
└──────────┴──────────────────────────────┴──────────────────┘
```

- **左ペイン**: 現在の「60ボタンのアコーディオン」を廃止。ページ構成ツリー(セクションのD&D並替・複製・削除)+「セクション追加」はカテゴリ+検索+サムネイルプレビュー付きモーダルに
- **右ペイン(コンテキストインスペクタ)**: 選択対象に応じて内容が変わる。セクション選択時=その`content`のフォーム編集+バリアント切替+AI再生成。非選択時=ページ設定(テーマ・SEO)
- **中央**: iframeプレビュー。クリックでセクション選択、ダブルクリックでインライン編集(編集結果はJSONへ書き戻し)
- モバイル幅ではペインをタブ化

### 5.2 主要フロー

- **新規作成**: ウィザード(§3.2)→エディタ。「白紙から手動で」の導線も残す
- **既存編集**: プロジェクト一覧(サムネイル付き)→エディタ。autosave(既存30秒を継続)+明示保存+リビジョン履歴
- **エクスポート**: 形式選択+プレビュー+「編集内容がすべて含まれる」ことの保証(§3.1により構造的に保証)

### 5.3 アクセシビリティ/操作性(ツール自身)

- インライン編集にキーボード経路(Enterで編集開始、Escで確定)とARIA付与
- `prompt()`/`alert()`(`generator.js:3088,1511`)を廃止しモーダル/トーストに統一
- `onclick="window.lpGenerator…"`のインラインハンドラ(`generator.js:3162-3172`)をイベント委譲に置換
- ダークモード統一(§3.3)。フォーカスリング・reduced-motion対応

## 7. 技術リファクタリング計画

**方針: フル書き換えではなく、資産を活かした段階的移行**(テンプレート51種・AI層・エディタ部品は再利用価値が高い)。

- **モジュール化**: `generator.js`(5.8k行)を ESM モジュールに分割 — `state/`(store+history)、`render/`(セクションレンダラ)、`ui/`(ペイン別)、`ai/`(既存を発展)、`export/`。Vite導入(dev server+バンドル+将来のTS化余地)。フレームワーク導入はこの時点では**しない**(Preact等の採用はPhase 1完了後に再評価)
- **CSS統合**: 12ファイル → `tokens.css`(全トークン、`:root`一元)/ `app.css`(ツールUI)/ `lp-base.css`+`lp-sections.css`(生成LP用、iframe内でのみ読込)/ `lp-themes.css`(プリセット)。未参照の`styles.css`、`sub.html`、`enhanced-generator.js`、`_style.scss`は削除
- **ダッシュボードジェネレーター**: 当面凍結(現状維持で同梱)し、LP側の新基盤が安定した後に同じデータモデル方式へ移行。二重実装を先に増やさない
- **テスト/CI**: Vitest(スキーマ検証・レンダラの純関数テスト・マイグレーション)+ Playwright(ウィザード→生成→編集→エクスポートのE2E)+ GitHub Actions(lint+test)。AI呼び出しはモック化
- **ドキュメント**: READMEを実装と同期(現状は機能数・構成とも乖離)。`TEST_ARCHITECTURE.md`/`MCP_SKILLS.md`は「構想」ラベルを明記 or アーカイブ

## 9. リスクと対策

| リスク | 対策 |
|--------|------|
| モデル価格/ラインナップの変動(「最安」が入れ替わる) | モデル定義を設定ファイル化し、UIに価格表示。四半期ごとに見直し |
| 安価モデルの日本語コピー品質が不足 | スキーマ制約+文字数制約+Few-shot例をプロンプトに同梱。検証失敗時のQualityティア昇格。人手編集がしやすいUIで補完 |
| 既存ユーザーのlocalStorageデータ互換 | `schemaVersion`マイグレーションをPhase 1で必須実装。変換不能時は旧形式のままJSONエクスポートさせる救済経路 |
| 段階移行中の二重実装コスト | セクション型の移行順を利用頻度で優先付けし、未移行型は「レガシー型」としてJSONに生HTMLを保持(閲覧専用) |
| ブラウザ直コールのCORS(特にOpenAI) | Gemini/OllamaはBYOK直コール、OpenAIはプロキシモード推奨と明記。接続テストUIで事前検知(既存`validateConnection`を活用) |
| スコープ肥大(ダッシュボード側・画像生成など) | Phase 0〜2ではLPジェネレーターのみに集中。画像生成は明示的にスコープ外 |

## 10. 意思決定が必要な事項

1. **Gemini Qualityティアの選択**: 価格順では`gemini-3.1-flash-lite`($0.25/$1.50)が2番目だが、`gemini-2.5-flash`($0.30/$2.50)の方が実績が長い。→ 推奨: 設定ファイルで両対応にし、デフォルトは実装時のベンチで決定
2. **フレームワーク導入の是非**: 本計画はVanilla+Vite+ESM分割を前提(移行リスク最小)。Phase 1完了時点でPreact/Svelte導入を再評価
3. **プロキシサーバーの運用**: 商品化(不特定ユーザー提供)するなら必須。個人/社内ツール止まりならBYOKのみで可
