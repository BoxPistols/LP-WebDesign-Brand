## 0. エグゼクティブサマリー

現在地を率直に言えば、我々は **「1枚もののLPを、少数だが高品質なテンプレートとAIブリーフ生成で作るツール」** であり、Mobiriseは **「マルチページのWebサイトを、2,400+ブロック・70+テーマ・AIの3〜4案一括生成・ワンクリック公開で作る総合ビルダー」** です。ブロック数(77 vs 2,400+)・マルチページ・公開機能・フォーム実送信・アセット管理で明確に劣後しています。

**しかし、ブロック数と機能数の物量でMobiriseを追うのは悪手です。** Mobiriseの公表された弱点は「カスタマイズの浅さ・テーマの反復感・生成AIの汎用性・コラボ/ブログ非対応・オフラインでサイロ化したファイル」。ここに我々の勝ち筋があります。

**戦略的ベット(3本柱):**
1. **AIネイティブ生成で超える** — Mobiriseの「3〜4案生成」に対し、我々は既にブリーフ→構成プラン→セクション生成の骨格を持つ(`js/ai/ai-ui-controller.js` `generateFromBrief`)。これを**マルチバリアント+反復リジェネ+マルチページ**へ拡張し、「汎用的で詰めが必要」なMobirise AIを、日本語の業種文脈まで踏み込んだ生成で上回る。
2. **デザイン品質で超える** — `DESIGN_CODEX.md` による検証可能な品質基準(充填率・レイヤー・禁止スタイル)と、日本型高密度LP・アワード級リッチ表現のアーキタイプ(`js/archetype-templates.js`)は、Mobiriseの「反復感あるテーマ」に対する明確な差別化。**量ではなく品質の下限保証**で戦う。
3. **サイロを持たないクラウド前提** — Mobiriseのオフライン・ファイルサイロに対し、我々はブラウザ/クラウドで完結し、自己完結エクスポート(`generator.js` の `generateCustomCSSHTML`、CSSインライン化済み)+将来のワンクリック公開で「プロのワークフロー」に乗る。

ただし、これらの差別化を載せる**土台(マルチページのデータモデル、ブロックカテゴリの網羅、per-blockの設定パネル)が未整備**であり、まずここを埋めないと「LPジェネレーター」の枠を出られません。

## 2. 重大ギャップ Top 8

### ① マルチページのデータモデルが存在しない 🔴
- **欠落**: `js/generator.js` の状態は `this.sections[]` の単一配列で、ページの概念(`pages[]`、currentPage、ページ間ナビ)が皆無(grep: `multiPage|pages\[|addPage` = 0ヒット)。
- **なぜ重要**: Mobiriseの本質は「サイト」を作ること。1枚LPしか作れない限り、ビルダーではなく「LPジェネレーター」に留まる。
- **修正**: プロジェクトJSONを `{ pages: [{ id, name, path, sections[], seo }], sharedHeader, sharedFooter, theme }` に再設計。全レンダー/保存/エクスポートをページ対応に。→ Phase F の最優先。

### ② navbar・footer・gallery・slider・map の専用ブロックが無い 🔴
- **欠落**: 77セクション中、ナビバー/フッター/ギャラリー/スライダー/マップの独立ブロックが不在(存在するのは `carousel-testimonials`、`logo-cloud` 程度)。カテゴリも `data-accordion` に navbar/footer 系が無い。
- **なぜ重要**: マルチページサイトはグローバルナビとフッターが必須。ギャラリー/スライダー/マップはあらゆる業種で要求される基本ブロック。
- **修正**: ナビバー(3+バリアント)・フッター(3+)・ギャラリー/メーソンリー・スライダー/カルーセル・マップ・タイムライン・ブログ一覧・ロゴ帯を追加。DESIGN_CODEX準拠で。→ Phase P。

### ③ フォームが実送信できない(静的デモ) 🔴
- **欠落**: エクスポートHTMLのフォームは `form.addEventListener('submit', e => { e.preventDefault(); alert('送信されました（デモ）') })`(`generator.js` 内)。実際のリード獲得ができない。
- **なぜ重要**: LP/サイトの目的はコンバージョン。送信できないフォームは商品として成立しない。
- **修正**: フォームビルダー(項目定義)+送信先(Formspree/自前エンドポイント/mailto/webhook)の設定UI。→ Phase P。

### ④ per-blockの設定パネルが無い 🟠
- **欠落**: セクション操作はホバー時の上下移動/複製/削除(`generator.js` `addSectionControls`)とインライン編集のみ。「このブロックの背景・余白・レイアウト・サブ要素の表示切替」といったパラメータ編集ができない。
- **なぜ重要**: Mobiriseの編集体験の中核。テンプレを選んで終わりではなく、ブロック単位で詰められることが「ビルダー」の条件。
- **修正**: 右インスペクタに選択ブロックの設定フォーム(背景色/画像/動画、上下余白、コンテナ幅、サブ要素トグル)。JSONデータモデル(§3)が前提。→ Phase P(データモデル後)。

### ⑤ ワンクリック公開・ZIP同梱エクスポートが無い 🟠
- **欠落**: エクスポートは単一HTML/コード生成のみ。ZIP(HTML+CSS+画像アセット)も、サブドメイン公開も無い(grep: zip=0、publish=タブ名のみ)。
- **なぜ重要**: 「作って終わり」から「公開して終わり」への距離。Mobiriseは無料サブドメイン公開が入口。
- **修正**: JSZipでアセット同梱ZIP → さらにNetlify/Vercel/GitHub Pagesへのワンクリックデプロイ(このセッションのMCP資産が活用可)。→ Phase P/X。

### ⑥ プレビューがiframe隔離されていない 🟠
- **欠落**: プレビューは `previewFrame.innerHTML = html`(`generator.js`)で、ツールUIと生成LPのCSSが同一カスケード。過去の「デザイン破綻」修正の温床。
- **なぜ重要**: ブロック数を増やすほどCSS衝突リスクが増大。スケールの前提条件。
- **修正**: `<iframe srcdoc>` 化。編集イベントはpostMessage/委譲で継続。→ Phase F。

### ⑦ AI生成が単一案・単一ページ 🟠
- **欠落**: `generateFromBrief` はプラン1つ→セクション逐次生成で1案のみ。多案比較・反復リジェネ・マルチページ生成・AI画像が無い。
- **なぜ重要**: MobiriseのAIの目玉が「3〜4案を並べて選ぶ」。ここは我々が**超えにいく**主戦場。
- **修正**: 配色/構成を変えた3案並列生成→サムネ比較選択、セクション単位の「作り直す」、ブリーフからマルチページ生成、AI画像(または高品質SVG/アンスプラッシュ連携)。→ Phase X。

### ⑧ 5,800行の神クラス+トークン重複でスケールしない 🟠
- **欠落**: `js/generator.js` が単一巨大クラス、デザイントークンが6 CSSファイルに重複、テスト/CIゼロ。
- **なぜ重要**: ブロック・ページ・設定パネルを足すほど破綻リスクが増す。品質担保の土台が無い。
- **修正**: ESMモジュール分割(state/render/ui/ai/export)+Vite導入+トークン一元化(`tokens.css`)+Vitest/Playwright+GitHub Actions。→ Phase F(段階的)。

## 5. 具体的な次の一手(このイテレーションで作るもの)

現状のコードに直接乗る、影響が大きく独立性の高い3つ:

1. **マルチページのデータモデル(F1)の第一歩** — `this.sections` を `this.project.pages[currentPageIndex].sections` へ移行し、ヘッダーに「ページ」タブ(追加/切替/リネーム)を追加。既存の保存データは「1ページのサイト」へ自動マイグレート。→ ビルダー化の分水嶺。**まずこれ。**

2. **共有ナビバー&フッター・ブロック(P1の起点)** — マルチページに必須なグローバルナビ(3バリアント)とフッター(3バリアント)をDESIGN_CODEX準拠で追加。ページ追加時に自動で共有ヘッダ/フッタが入る導線。

3. **ZIP+アセット同梱エクスポート(P4)** — JSZipで現行の自己完結HTML(CSSインライン済)に画像アセットを束ねてZIP化。単一ページでも即価値が出るクイックウィン。マルチページ化後はそのまま全ページ書き出しに拡張。

> 補足: 批評レビュー(下記)で「F1マルチページを入れる前に、まずF2 iframe隔離とデータモデルのJSON化を土台として固めるべき」という指摘があれば、順序はそちらを優先する。土台の順序は実装着手時に再確認する。

## 付録: 我々が既に持つ優位(Mobiriseに対して守るべき資産)

- **AIブリーフ生成の骨格**(`js/ai/`)— 業種/目的/ターゲット/トーン/強み/CTAから構成プラン→セクション生成。Mobiriseの汎用プロンプトより文脈が深い。
- **DESIGN_CODEX品質基準**(`docs/DESIGN_CODEX.md`)— 検証可能な品質の下限。禁止スタイル(片側太ボーダー+角丸等)の機械的排除。
- **日本型高密度+アワード級リッチのアーキタイプ**(`js/archetype-templates.js`、17種)— Mobiriseの反復的テーマにない、市場特化の高品質。
- **自己完結エクスポート**(CSSインライン化済、CDN非依存)+ 9つの出力形式。
- **スクロール演出ランタイム**(`js/lp-motion.js`)— 出現/パララックス/カウントアップ、reduced-motion対応。
